# R argument names vs the CRAN release (decision D3)

**Decision (2026-10-28):** keep CRAN names where the meaning is the same;
otherwise name the tolerance after what it controls:

- `reltol`: relative step (the CRAN meaning), e.g. lomax, weibull, beta;
- `abstol`: absolute step (gamma family, fatigue, burr's log-shape step);
- `gradtol`: gradient norm (the six BFGS fitters; the name `nlm` uses);
- `iterlim`: iteration limit (CRAN name everywhere);
- `<param>0`: optional start value (`lambda0`, `shape0`, `a0`, ...), restored
  where CRAN had one, `NULL` meaning the automatic start.

No `tol` aliases: `tol` was never released. Renames are applied per
distribution as each one moves to its own folder
(roadmap/2026-10-28-per-distribution-layout.md). The table below is the
Codex audit (gpt-6.1-sol, low) the decision is based on; its "proposed
final names" column predates the decision.


This read-only audit compares all 42 CRAN fitters at `c0b9949` with the current generated R interface, Rcpp adapter signatures, and actual C++ convergence tests, and proposes R-facing names under D3. It distinguishes documented controls from controls the historical code really used; no package code was changed and no builds or tests were run. `origin/master` resolves to the same full commit, `c0b9949bbc2201e8a51dc7f04b06931b8627bfe1`, so both historical references agree.

All rows omit common `x`, `na.rm=FALSE`, and `...`; generated wrappers forward dots directly to adapters. Historical exp/naka documentation stubs say `na.rm=TRUE`, but the historical decorator in `R/helpers.R` actually supplies FALSE uniformly. E4 means `.Machine$double.eps^0.25` (=0.0001220703125); E2 means its square root (=1.4901161193847656e-08). Proposed numerical defaults preserve current adapter literals unless explicitly noted; these are rounded, not exact E4/E2. “Breaking?” describes CRAN → current drift and/or current → proposed changes, not identical numerical estimates across different algorithms. Keep deprecated `tol` aliases for proposed renames, rejecting conflicting simultaneous values.

B: BFGS also stops when max absolute phi step < `1e-8*(max abs old phi+1e-8)` OR objective decrease < `1e-12*(abs(old f)+1e-12)`. These fixed backstops are not controlled by the exposed tol. No fitter currently exposes an objective-relative tolerance. Gradient norms refer to the total, not per-observation, objective and depend on sample size and parameter transformation.

## Disappeared controls, restoration, and meaning changes

- Easy naming restorations: beta/betapr expose a genuinely relative test in log(shape2); gumbel/weibull/invweibull expose a relative test in log(Gumbel sigma). Rename their adapter control to `reltol`, retain a `tol` alias, and document the coordinate. Beta/betapr controls are new functionality: CRAN hardcoded them, and the current default is E2 rather than CRAN's E4. Gumbel's coordinate changed from sigma to log(sigma); its current test degenerates at theta=0 (sigma=1). Restoring the name does not restore that old convergence rule.
- Lomax, Kumar, Gompertz, negative binomial and Zipf lost the accepted `reltol` spelling. The proposed `reltol` is a mixed relative/absolute step criterion with a unit floor, explicitly documented as such. It can be much looser near zero than CRAN's pure relative step. For strict semantic compatibility, change the rule back to the CRAN relative test, or expose separate absolute and relative tolerances; a name-only adapter change cannot achieve that. Kumar additionally applies the same control and iteration budget independently to two stages.
- Gamma, inverse gamma, loggamma, Nakagami and fatigue lost `reltol` and now stop on an absolute natural-parameter step. Calling that `reltol` would be misleading. Proposed `tol` retains today's meaning; restoring CRAN's `reltol` faithfully needs a relative stopping-rule option in the core. Do not silently alias `reltol` to the absolute threshold. Binomial also uses an absolute size step now, but CRAN never forwarded its documented controls to Newton; implementing those promises would add behavior rather than restore functioning controls.
- Burr accepted `reltol`/`iterlim` despite docs saying dots did nothing. It now uses an absolute log(shape2) step, approximately a relative natural-shape step only locally. Keep `tol` and document its coordinate, or add a genuine relative natural-shape test for `reltol`; a direct alias changes semantics. Inverse Burr did not forward its dots and now fits reciprocal data through Burr, so its new controls and algorithm are not restored CRAN behavior.
- Cauchy, logistic and loglogistic have absolute mixed-coordinate step tests; their `tol` should remain `tol`. The five fGarch-based fitters plus paralogis use gradient-norm thresholds: `reltol` would be misleading. Keep `tol` (document it as gradient tolerance; `grad_tol` would be a clearer future expansion). CRAN did not forward user optimizer controls to fGarch or nlm. These new controls cannot be described as preserved CRAN optimizer settings.
- Preserve `iterlim`, fixed binomial `size`, and power `epsilon`. Restore numeric double acceptance for negative-binomial `size`; the present `Nullable<int>`/`as<int>` conversion loses fractional sizes that CRAN accepted. `size` fixes a model parameter; it is not a start value. Power's epsilon changes the endpoint estimate and is not a stopping tolerance. Rounded literal defaults should be an explicit compatibility decision, separate from names.
- CRAN ignored arbitrary dots in many fitters; generated wrappers now forward them to signatures without a catch-all, so formerly ignored arguments can error. A reviewer should decide whether strict rejection is intentional; this is distinct from restoring supported named controls.

## Start values

| fitter | CRAN start behavior | can today's C++ fitter accept a start? | proposed restoration |
|---|---|---|---|
| lomax | `lambda0` overrides `1/(m*(alpha0-1))`, where `alpha0=2*(s-m²)/(s-2*m²)`, m=mean(x), s=mean(x²) | No; `lomax_mle(x,tol,maxit)` computes lambda internally | Add optional core start and R `lambda0=NULL`; NULL means automatic moment estimate |
| kumar | `a0=1`, optional override | No; `kumar_mle` estimates an L-moment start then runs full ML | Add core start that bypasses automatic start stage and R `a0=NULL`; choose `a0=1` as default instead if exact historical initialization is required |
| weibull / invweibull | `shape0` documented (inherited by inverse Weibull) but ignored: Gumbel helper never reads it | No; both call `fit_gumbel_newton` with an internal start | Implement promised `shape0=NULL` by supplying Gumbel sigma0=1/shape0 (theta0=-log(shape0)); document that this is newly functional |
| paralogis | Undocumented but effective `shape0`; default `max(3/(1-mean(x)),0.1)`; scale fixed at 1 | No; `paralogis_mle` builds both log-shape and log-scale starts internally | Add optional shape start; `shape0=NULL` keeps current automatic start; clarify that fitting scale is an accepted model generalization, not a recovered CRAN fit |
| burr | No documented/named start override; fixed automatic c0 | Yes: `burr_mle_core(x,c_start,tol,maxit)`; adapter already exposes `init=NULL`, uses first numeric element as c=shape2 | Keep `init=NULL`; document scalar positive shape2, not the full parameter vector |

No other CRAN fitter reads a named user start. Local variables such as gamma's shape0 and Zipf's shape0 are internal and do not constitute supported user controls. Implementing the first four restorations needs small core/API work, not just edits to generated wrappers; none is implemented by this audit.
