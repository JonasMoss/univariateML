**Field precedence and adapter context.**

- `accuracy_stop` maps Tolerance/Conditioning to the corresponding failure reason for tbinom, zib, zmbinom, ztbinom, zinb, ztnbinom and tnorm; zmnbinom reads it on `IterationFailure`. Zib/zmbinom/ztbinom additionally map `accuracy_failure` to `F(NoConvergence)`. The four binomial kernels then read budget before comparison-tie flags on non-Ok results: `B` or `F(Unresolved)`. Successful uncertified fallbacks remain `E(c)` even with retained certificate flags.
- Nbinom's certificate Budget flag precedes its enum mapping. Failed ztnbinom/zmnbinom searches use their budget flag for `B`, Arithmetic for `F(Evaluation)`, otherwise `F(NoConvergence)`. Zinb's `IterationFailure`/`ZeroLimit` paths read certificate Budget → `B`, ComparisonTie → `E(false)`, TailUnresolved → `F(Unresolved)`; Arithmetic on `IterationFailure` gives `F(Evaluation)`. Workload/other failed searches retain `F(NoConvergence)`.
- Tnorm's recorded comparison tie gives `E(false)` and retains the existing literal `tie` stop. Analytic boundary results without that flag give `L(true)`. Tpois/tbinom singleton-support ties give `unique=false`; ZIP/ZIB/ZINB comparison-margin ties withdraw certification rather than claiming proved equality. Finite-window zeta reads its explicit unidentified flag.
- Tnorm `InvalidBounds` also has an adapter-only constant-data/hold/control predicate that emits `nomle`; that branch attaches `N(Unbounded)`. Its existing classification guards can suppress a statistical stop for invalid original data/controls or an unusable payload; suppressed stops attach `F(Evaluation)`. The core result lacks that caller context. These decisions and messages are unchanged.
- The seam attaches the preliminary generic Poisson solve only when it rejects the fit; otherwise the private tpois call decides the outcome. Coordinate/name rewrites preserve the kernel outcome. Fully held windows have no core call: finite direct likelihood evaluation gives `E(true)`, with status −1; existing rejections attach failures. Other pre-core rejections use `invalid_argument`.

**Observed core-success overrides:** none in any final snapshot. Existing post-core rejection guards now attach `overridden` when refusing an estimate; no numerical repair was made.
